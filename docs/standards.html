Standards & sources

The harness builds on about 35 public standards and practices across eight areas. Each one is written into a specific agent, rule or check, so the agents apply it on every change instead of leaving it to the prompt.

What the harness is built on

AI Dev Harness is a governed delivery framework for AI-assisted software development. It runs on Claude Code and turns AI coding from ad-hoc prompting into a repeatable engineering process: specialist agents for analysis, architecture, development, testing, review, security and release work through defined workflows, and a person approves each gate.

Its rules are not invented. Code quality follows Robert C. Martin's Clean Code and SOLID principles. Testing follows test-driven development, the test pyramid and Given/When/Then acceptance criteria. Security follows the OWASP Top 10 and least privilege, and accessibility targets WCAG 2.1 AA. History and releases follow Conventional Commits, Semantic Versioning and Keep a Changelog, and decisions are kept as Architecture Decision Records.

What makes these standards hold is enforcement. An automated quality gate checks every change for build, tests, coverage of the changed lines, complexity, CRAP score, mutation score, suppressed warnings and removed tests. Hooks block unsafe actions such as force pushes and requests to production hosts. No agent can call work done by weakening a check. Teams get AI-speed delivery with the predictability, traceability and quality controls they already expect from good engineering.

Each table names the standard, where the idea comes from, and the harness file that applies it. The Origin column credits the idea's author or publisher; the harness files name the standards but mostly don't link them. Paths are relative to the repository root.

1. Code quality & the quality gate

The gate (.claude/scripts/quality-gate.sh) follows Robert C. Martin's view that a professional proves code works before calling it done, and never makes a check pass by weakening it. See Quality gate in the guide for how it runs.
