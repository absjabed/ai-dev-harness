AI Harness

A governed AI development lifecycle for Claude Code. Copy it into a repo, answer one interview, and specialist agents deliver features through the same gates, standards and guardrails every time.

What it is

The harness replaces ad-hoc prompting with a delivery model: specs before code, a human approving at every gate, and automated checks that run whether or not the model cooperates. It is a template — every project-specific value is a {{TOKEN}} or a [FILL IN] block until you configure it.

16 agent personas

BA, architect, designer, developer, QA, reviewer, security, DevOps, PM, release, orchestrator, critic and more.

26 slash commands

Studios, specialists, workflows, utilities and harness maintenance.

8 automated hooks

Block force pushes and protected-branch pushes, type-check and lint after edits, warn on sensitive files.

Resumable workflows

STATE.md records phase, tasks and decisions, so a fresh session picks up exactly where the last one stopped.

Why use it

AI can already write the code. What it does badly, left unsupervised, is everything around the code: knowing this project's conventions, proving the change works, and stopping before something irreversible. That gap is what the harness closes — each mechanism below answers a specific failure mode, not a slogan.

Without a harnessWhat the harness does
You re-explain the stack, conventions and domain every session — and the answers driftThe filled .ai/config/ and .ai/context/ are loaded automatically, scoped to the task. The project's rules are a file, not a memory of a prompt
Output quality depends on how well you phrased today's promptPersonas and playbooks fix the method. /agents:review applies the same severity vocabulary on a Friday as on a Monday
AI-written code lands with a glance, because reviewing it is slower than accepting itReviewer and security scanner run in parallel, read-only, on the diff. CRITICAL findings block the commit — the gate isn't optional and isn't yours to forget
"Tests pass" — but nobody checks whether tests exist for that scopeVerification is scope-aware: real tests where a runner exists, a clean build plus a documented manual reproduction where none does, and the report states which happened
One bad command — a force push, a hard reset, a deploy to prod — undoes a dayHooks hard-block them at the tool call, before the model's intent matters
Why a decision was made lives in a Slack thread that's now goneAppend-only decisions, learnings and design-taste logs. The designer reads rejected patterns before proposing, so a "no" stays a no
A long session loses the thread, and the next one starts coldSTATE.md records phase, tasks and decisions; re-running resumes and re-verifies each "done" phase's artifact before trusting it
Parallel work on one feature collides in the working treeThe epic path gives each sub-feature its own git worktree, merged in dependency order
Every repo grows its own private way of working with AIThe same harness, the same commands, the same gates across projects. A joiner learns it once

What it costs

Ceremony. The full path — /ba → /qa → /workflows:feature with five STOP gates — is built for work that deserves a spec. For a typo or a one-line fix that overhead is real and not worth paying: use /agents:dev or /workflows:bugfix instead. The harness also can't make a codebase testable, and it won't catch a bad decision you approve at a gate. It removes the failures that come from forgetting, not the ones that come from judgment.

Setup in 4 steps

  1. Copy the harness in

    From a clone of the template repo, copy into your project root:

    .ai/  .claude/  .mcp.json  CLAUDE.md  COMMANDS.md  README.md

    Optionally bring examples/fleetkeep/ for reference while configuring.

    Don't copy the template's .gitignore. Your project needs .worktrees/ ignored — and must not ignore .ai/features/, because the epic path commits planning artifacts for worktrees to read.

  2. Run /init-project

    It interviews you across identity, repo topology, stack, commands, conventions, version control, security, design system, risk profile and branding — then fills every skeleton and writes .claude/hooks/hooks.env.

    Shape the tree while you're there: single-project repos delete the backend/ and frontend/ subfolders; headless projects delete the design subtree; unused per-stack reference folders can go.

  3. Verify nothing is unfilled

    grep -rn '{{' .ai CLAUDE.md .claude/hooks/hooks.env | grep -vE 'CUSTOMIZATION.md|agents/harness-|workflows/harness-improvement|templates/artifact-header|standards/project/[a-z]+/(dotnet|node|react|angular)/|standards/universal/vcs/|examples/'

    Empty output means done.

  4. Switch the guardrails on

    hooks.env is inert-safe: a blank value or *_CHECK="off" skips that check silently. An un-customised file blocks nothing while looking fully installed.

    KeyIf left unset
    PROTECTED_BRANCHESDirect pushes to main/develop aren't blocked
    TYPECHECK_CMD / LINT_CMD + PACKAGE_DIRSNo checks run after edits
    MIGRATIONS_GLOBGenerated migrations can be hand-edited silently
    SENSITIVE_CONFIG_GLOBSNo warning before editing secrets-bearing config
    TENANT_ISOLATION_CHECK + TENANT_KEYNo tenant-scoping check on data access

    Smoke-test it: on a protected branch, ask Claude to git push --force and confirm it refuses.

Hooks & guardrails

HookEventWhat it does
git-guard.shPreToolUse (Bash)Blocks git push --force, git reset --hard, pushes to protected branches, deploys to the production stage
pre-tool-use.shPreToolUse (edits)Warns or blocks before editing generated migrations and sensitive config
post-tool-use.shPostToolUse (edits)Type-check + lint for the edited package; tenant-isolation, frontend-env, design-token and TDD checks
post-tool-batch.shPostToolBatchFull-project type-check after parallel edits
post-tool-failure.shPostToolUseFailureClassifies the failure and feeds back a hint
stop-check.shStopFlags uncommitted changes on feature/epic branches
user-prompt-context.shUserPromptSubmitInjects current branch and active scope
compact-restore.shSessionStart (compact)Re-injects orientation after compaction

All behaviour comes from .claude/hooks/hooks.env — 25 keys covering version control, deploy guard, repo layout, quality commands, sensitive files, tenant isolation, frontend env, design tokens and the TDD nudge. Warnings go to stderr and are non-blocking; only the git guard and sensitive-file rules hard-block.

Workflows

Playbooks in .ai/workflows/ are the method the commands follow — edit a playbook and the matching command changes behaviour. They cover feature development, bug fixing, hotfixes, releases, code review, story generation, and harness improvement.

The epic path

When /ba produced an epic-breakdown.md, the feature workflow switches to six phases:

A validate→B design gate→C epic branch→D parallel build→E sequential merge→F review + PR

Phase D isolates each sub-feature in its own git worktree under .worktrees/, so delegated agents never share a working tree. Worktrees only see committed files — which is why planning artifacts are committed onto the epic branch first.

The first three are committed — the harness's institutional memory. The designer reads design-taste before proposing, so a rejected pattern stays rejected.

Scope model

Every context-loading command resolves a scope first: a forced scope in .ai/config/current-scope.md wins; otherwise it infers backend / frontend / fullstack from your request using the stack signals filled in at init, and loads only that scope's config, context and standards. Force it with /utils:scope backend; release it with /utils:scope auto.

Other AI agents

The harness splits into a method that travels and an enforcement mechanism that does not. .ai/ is 82 files of plain markdown with no tool-specific syntax. The Claude Code coupling sits in the 26 commands (73 @file includes, 108 $ARGUMENTS refs), the 8 sub-agents, and the 8 hooks wired to Claude Code's event names.

StepWhat it gives youCost
AGENTS.md doneThe whole method as instructions — which files to read, how to scope, which playbook, the five gates, the guardrails to self-enforce. Works with Codex, Cursor, Gemini, CopilotNone ongoing; it defers to CLAUDE.md and .ai/ so it can't drift
Git hooks + CIGuardrails that hold regardless of who edits — agent or human. Recipes for pre-push and pre-commit that re-use hooks.env verbatimAbout half a day; CI is the real boundary since --no-verify skips local hooks
Command generatorsSlash-command ergonomics inside one specific non-Claude toolHighest — generated output rots on every harness change unless CI fails on staleness

Three things never port: hard blocks at the tool call, read-only sub-agents that cannot edit what they review, and parallel isolated review. Elsewhere those become instructions, and instructions are advisory.

Full detail, recipes and the support matrix: docs/portability.md.
